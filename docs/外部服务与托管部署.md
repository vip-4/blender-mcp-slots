# 外部服务接入与托管部署

本文说明三类外部资源如何接入本模块：**Neon Postgres（持久化）**、**Redis（旁路热数据）**、**代码托管（GitHub / Gitee / AtomGit）**，以及生产部署与稳定性约定。

> 安全约定：所有密钥只写入本地 `.env`（已被 `.gitignore` 排除）或部署平台的环境变量，**绝不进入仓库**；推送后请轮换曾出现在命令行历史中的 token。

---

## 1. Neon Postgres（旋转审计 + 排行榜）

### 1.1 准备连接串

1. 在 Neon 控制台创建项目 / 数据库（本项目使用 `neondb`，角色 `neondb_owner`）；
2. 通过 Neon API 获取连接串（脚本化，避免手抄出错）：

```bash
curl -s "https://console.neon.tech/api/v2/projects?org_id=<org_id>" -H "Authorization: Bearer $NEON_API_KEY"
curl -s "https://console.neon.tech/api/v2/projects/<project_id>/connection_uri?branch_id=<branch_id>&database_name=neondb&role_name=neondb_owner&org_id=<org_id>" \
  -H "Authorization: Bearer $NEON_API_KEY"
```

3. 写入 `.env`：

```env
DATABASE_URL=postgresql://neondb_owner:***@<endpoint>-pooler.<region>.aws.neon.tech/neondb?sslmode=require
STORE_DRIVER=auto
```

### 1.2 建表（幂等）

```bash
npm install          # 安装可选依赖 pg
npm run migrate      # 等价于执行 db/schema.sql
npm run migrate -- --check   # 额外打印 slot_spins 行数
```

表结构：

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `slot_spins` | 每一轮的审计流水 | `round_id`、`session_id`、`game_id`、`phase`、`bet/cost/total_win`、`multiplier`、`triggered(jsonb)`、`server_seed_hash`、`nonce` |
| `slot_leaderboard` | 每个会话在每台机台上的最佳战绩（按 `best_multiplier` 排序） | `game_id + session_id` 主键，upsert 取最大值 |
| `slot_sessions` | 会话留痕（预留，便于对账） | `id`、`game_id`、`bet`、`lines`、`balance` |

### 1.3 运行期行为

- **写入**：`GameService.persist()` 旁路调用 → 入队 → 批量事务落库（一次 `insert ... values (...),(...)` + 一次 `unnest` upsert）。
- **读取**：`slots.history` 读前先补写队列，保证「刚转完就能查到」。
- **失败**：连接失败 / 语句报错 / 依赖缺失，全部降级到内存后端，`store.health` 返回 `degraded: true`，旋转接口不受任何影响。

验证：

```bash
curl -X POST http://127.0.0.1:5173/rpc -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"store.health"}'
# → primary.driver=postgres, primary.ok=true
```

## 2. Redis（可选旁路缓存）

```env
REDIS_URL=redis://default:<password>@<host>:<port>
```

- 实现为**零依赖 RESP 客户端**（`src/store/redis.js`），仅支持 `AUTH/PING/RPUSH/LTRIM/LRANGE/ZADD/ZREVRANGE`，不引入 `ioredis`；
- 用途：最近旋转列表（`slots:spins:<gameId>`）与排行榜 ZSET（`slots:board:<gameId>`）；
- 默认**不启用**：`STORE_DRIVER=auto` 且无 `DATABASE_URL` 时才作为主存储；否则仅作旁路。
- 当前环境实测：所提供的 Redis 端点 DNS 无法解析（`ENOTFOUND`），因此自动降级，不影响服务；换用可用端点后无需改代码，仅配置 `REDIS_URL` 即可。

## 3. 代码托管与推送

仓库（公开）：

| 平台 | 地址 |
| --- | --- |
| GitHub | `https://github.com/<owner>/blender-mcp-slots` |
| Gitee | `https://gitee.com/<owner>/blender-mcp-slots` |
| AtomGit | `https://atomgit.com/<owner>/blender-mcp-slots` |

首次推送（带凭据一次性写入，随后移除凭据）：

```bash
git init && git add -A
git commit -m "feat: ..."
git remote add github https://<user>:<token>@github.com/<owner>/blender-mcp-slots.git
git push -u github HEAD:main
git remote set-url github https://github.com/<owner>/blender-mcp-slots.git   # 清除明文 token
```

多平台同步：为每个平台各建一个 remote，逐个 `git push`；或使用镜像推送：

```bash
git remote set-url --add --push origin https://gitee.com/<owner>/blender-mcp-slots.git
git remote set-url --add --push origin https://atomgit.com/<owner>/blender-mcp-slots.git
```

CI 建议（GitHub Actions 示例）：

```yaml
- run: npm install
- run: npm run test                       # 27 个用例
- run: npm run simulate -- 50000          # RTP 回归（可选断言区间）
```

## 4. 部署清单

1. `npm install`（可选依赖缺失亦可启动）；
2. 配置 `.env` / 环境变量：`DATABASE_URL`、`REDIS_URL`（可选）、`MCP_HTTP_PORT`、`MCP_LOG_LEVEL`；
3. `npm run migrate`（仅首次或表结构变更）；
4. 启动：`npm run start:http`（HTTP + 静态站）或 `npm run start:stdio`（MCP 客户端拉起）；
5. 健康检查：`GET /healthz`、`POST /rpc → system.health`（含 `store` 字段）、`GET /metrics`；
6. 优雅关闭：监听 `SIGINT/SIGTERM`，关闭会话清扫定时器并释放存储连接池。
