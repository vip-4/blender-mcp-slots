# SLOT GAMES 合集 · 需求与开发任务说明书（完善版）

> 目标：在既有 **Blender MCP** 框架中扩展老虎机（SLOT）游戏模块，把「单个老虎机项目」升级为
> **多款 SLOT 游戏的合集**，并让**多主题机台共用同一套 CONFIG 引擎**。
> 本文档在保留原始意图的前提下，补全功能范围、约束条件与实现方向，形成可直接执行的开发任务说明。

---

## 一、背景与问题定义

| 维度 | 现状 | 目标 |
| --- | --- | --- |
| 机台数量 | 单一机台，玩法与参数写在逻辑里 | 多机台合集，机台 = 一份纯数据 CONFIG |
| 引擎复用 | 转轮/判定/特性与主题耦合 | 一套 CONFIG 引擎驱动全部主题（lines / ways 双模式） |
| 接入方式 | 与已部署游戏接口不一致 | 统一入口（`slots.*` 工具），与既有 MCP 服务同构 |
| 参数调整 | 改代码 | 改 CONFIG / `tuning.payScale` + 热重载 |
| 可信度 | 随机结果不可复核 | 可证公平（seed + nonce）+ 蒙特卡洛自检 |

**一句话目标**：新增一款机台的开发成本 = 写一份 CONFIG 数据（不含引擎与前端改动）。

## 二、原始需求澄清（问题 → 决策）

| 原始表述 | 澄清出的关键问题 | 决策 |
| --- | --- | --- |
| 「扩展老虎机游戏模块」 | 是加机台还是加引擎能力？ | **两者都要**：引擎能力以「特性」方式沉淀，机台以 CONFIG 声明 |
| 「至少新增一款热门 SLOT」 | 新增几款、如何才算齐？ | 本次 3 款新机台（龙 / 法老 / 霓虹）+ 1 款基线机台保留为回归基准 |
| 「统一入口调用」 | 入口指什么？ | MCP 工具层单一门面 `slots.*`；HTTP 与 stdio 双传输共用同一 dispatcher |
| 「支持参数配置」 | 运行时可调还是改文件？ | 二者兼备：`slots.registerGame`（运行时注入）、`slots.reloadConfigs`（热重载）、`tuning.payScale`（赔付微调） |
| 「与现有 MCP 服务通信」 | 上游不可用时怎么办？ | 旁路化 + 熔断 + 超时 + 降级，主流程绝不因上游故障失败 |
| 「保证运行稳定性」 | 稳定性如何度量？ | 限流 / 幂等 / 预算 / TTL / 超时 / 优雅退出 / 指标端点，且均有测试 |
| 「前端展示与交互」 | 是否必须？ | 必须：提供大厅 + 机台 + 赔付表 + 特性演出，主题由 CONFIG 驱动 |

## 三、功能范围

### 3.1 In Scope（本次交付）

1. **共享 CONFIG 引擎**：RNG、转轮条带、线组、中奖判定（lines / ways）、特性、封顶、自检。
2. **机台合集**：8 台（1 基线 + 7 新增），各自主题、线制、特性、赔付表、RTP 目标。
3. **MCP 服务与统一入口**：`slots.* / blender.* / system.*` 工具；stdio + HTTP 双传输。
4. **会话与状态机**：基础轮 / 免费旋转 / 金币重旋三态自动流转。
5. **Blender 桥接**：健康检查、熔断、超时、降级。
6. **前端界面**：大厅、机台、转轮演出、中奖连线、特性横幅、赔付表、统计面板。
7. **稳定性与观测**：限流、幂等、预算、TTL、超时、优雅退出、`/healthz`、`/metrics`。
8. **外部存储与榜单**：Neon Postgres 持久化旋转流水与排行榜、Redis 旁路缓存、Cloudflare R2 流水归档与 CONFIG 快照、内存兜底与自动降级。
9. **新玩法引擎能力**：雪崩连锁（消除/下落/倍率阶梯）与扩展符号（整轴展开），两者均为 CONFIG 开关，不写死在机台里。
10. **测试与自检**：33 个自动化用例 + RTP 蒙特卡洛脚本 + 端到端冒烟脚本。

### 3.2 Out of Scope（明确排除）

- 真金钱包 / 支付 / KYC / 实名（仅提供 `WalletAdapter` 接口与演示内存账本）。
- 第三方认证鉴权、审计合规报表、多租户。
- 真金账务下的审计合规留存（旋转流水写入 Neon 仅用于审计与榜单，不等同于账务系统）。
- 真实 Blender 3D 建模与渲染（只做协议桥接与降级）。
- 移动端原生壳、离线缓存。

### 3.3 后续可选（不阻塞本次）

- `gamble`（猜双倍）、`bonusBuy`（购买特性）、`Megaways` 式变轴、奖池累积（Progressive）。
- 会话持久化到 Redis、钱包适配真实账务、管理后台调参界面。

## 四、功能需求（FR）

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| FR-01 | **转轮逻辑**：CONFIG 符号权重 → 确定性转轮条带；旋转 = 随机停止位；支持 `base/free/respin` 多套条带 | 同 CONFIG 在任意进程构建出的条带完全一致；有权重符号必出现 |
| FR-02 | **中奖判定**：`lines`（左起连续，含 WILD 替代、线注结算）与 `ways`（相邻轴任意位置，按组合数结算）双模式；`minMatch` 可配 | 已知盘面的赔付可解析计算，单测覆盖 |
| FR-03 | **散射与特殊符号**：scatter 任意位置计数并按总注结算；bonus（金币）触发重旋；collect（收集）兑现盘面金币面值 | scatter 计数、bonus 定位、collect 结算均有断言 |
| FR-04 | **奖励触发**：免费旋转（散射数量 → 次数，可再触发，倍率递进，上限可配） | 触发后 `cost=0`、`remaining` 递减、结算回基础轮 |
| FR-05 | **特殊符号功能**：扩张 WILD（整轴变 WILD，可黏性）、倍率 WILD（x2/x3/x5） | 盘面改写与倍率参与结算有单测 |
| FR-06 | **Hold & Respin**：N 枚金币触发 M 次重旋，新金币重置计数，锁定格保留，结束按面值合计 + 四档固定奖池 | 触发 → 锁定 → 重置 → 结算闭环，有限轮次内必结束 |
| FR-07 | **封顶**：单轮赢利不超过 `limits.maxWinMultiplier × 总投注` | 触发时 `capped=true`，金额等于封顶值 |
| FR-08 | **统一入口**：全部能力经 `slots.*` 工具；`tools/list` + `tools/call` 标准 MCP 形式 | 任一机台都能被 `tools/call slots.spin` 驱动 |
| FR-09 | **参数化配置**：`slots.registerGame` 运行时注入、`slots.reloadConfigs` 热重载、`tuning.payScale` 赔付微调 | 注入后立即可玩；`payScale` 线性生效 |
| FR-10 | **资金守恒**：`余额 = 起始 − 投注 + 返还` | 500 轮连续对账零误差 |
| FR-11 | **可证公平**：`serverSeed+clientSeed+nonce` 决定结果，返回 `serverSeedHash` | 同种子序列完全可复现 |
| FR-12 | **自检能力**：`slots.simulate` 输出 RTP / 命中率 / 最大倍率 / 波动指数 / 特性触发次数 | 各机台实测 RTP 落在目标 ±1.5% |
| FR-13 | **Blender 通信**：`blender.health` / `blender.renderSpin`，上游故障降级不阻断 | 未配置返回 `degraded`；连续失败触发熔断 |
| FR-14 | **前端大厅/机台**：卡片列表、转轮网格、中奖连线、特性横幅、投注/线数/自动、赔付表、统计、连接状态 | 全流程可玩，主题由 CONFIG 驱动 |

## 五、非功能需求（NFR）

| 类别 | 指标 |
| --- | --- |
| 性能 | 单次 `slots.spin` 服务端 P95 < 20ms（纯内存计算，无 IO）；`slots.simulate` 20 万轮 < 60s |
| 稳定性 | 单份 CONFIG 损坏只下线该机台；上游 Blender 故障不影响主流程；进程遇未捕获异常记录后继续 |
| 容量 | 会话上限 500（LRU + 30min TTL）；单会话旋转预算 2 万次；限流 120 容量 / 40 每秒补充 |
| 可观测 | `/healthz`、`/metrics`（调用量、耗时、最近错误、内存）；结构化 JSON 日志走 stderr |
| 安全 | 幂等键防重复扣款；静态目录防穿越；请求体大小上限；stdio 通道仅输出 JSON-RPC |
| 可维护 | 新增机台不改引擎/前端代码；CONFIG 契约集中在 `_schema.js`；引擎纯函数可单测 |
| 可移植 | 零第三方依赖（Node ≥18.17 即可运行）；可选接入官方 MCP SDK |
| 合规 | 演示账本与真实账务解耦，`WalletAdapter` 预留替换点；RTP 目标与实测均可审计 |

## 六、数据契约：CONFIG（多机台共用引擎的唯一数据源）

```
CONFIG := {
  id, name, version, provider,
  theme:   { key, tagline, primary, secondary, accent, background[], frame, font },
  grid:    { reels, rows },
  evaluation: { mode: 'lines'|'ways', direction, lineSet|ways, minMatch },
  symbols: [{ id, kind:'standard|wild|scatter|bonus|collect', label, shape, color,
              weight: number|perReel[], pay: {3:x,4:x,5:x}, payBasis:'line'|'totalBet' }],
  reelSets: { base:{length, overrides?, exclude?}, free?:{}, respin?:{} },
  bet:     { currency, levels[], default },
  features:{
    freeSpins?:      { trigger:{symbolId,counts}, reelSet, multiplier:{start,onRetrigger,max},
                       retrigger:{counts,maxSpins}, expandingWild:{reelIndexes,probability,sticky},
                       expandingSymbol:{ minCount, candidates[], reels? } },
    holdAndRespin?:  { trigger:{symbolId}, triggerCount, respins, coin:{values,weights},
                       jackpots:{mini,minor,major,grand}:{cells,multiplier} },
    collect?:        { symbolId, reels[], coin:{values,weights} },
    multiplierWild?: { values[], weights[] },
    cascades?:       { ladder[], maxSteps, removeWild, carryInFreeSpins }
  },
  tuning:  { payScale },            // 运营调参（赔付表全局系数）
  limits:  { maxWinMultiplier },
  rtp:     { target, tolerance },
  volatility: 'low'|'medium'|'medium-high'|'high'
}
```

**约束**：`id` 唯一且 kebab-case；scatter 的 `payBasis` 用 `totalBet`；`freeSpins.trigger.symbolId` 必须 `kind=scatter`；
`expandingSymbol.candidates` 只能取 `kind=standard` 且带赔付表的符号，`minCount ≥ 2`；
`cascades.ladder` 为正向倍率阶梯，`maxSteps ≥ 1`，`carryInFreeSpins=true` 时倍率在整段免费旋转内跨轮累积（默认 false：每轮从阶梯起点重来）；
`holdAndRespin.trigger.symbolId` 必须 `kind=bonus`；`bet.levels` 严格递增且包含 `default`；
`limits.maxWinMultiplier > 0`。加载期强制校验，违规机台单独下线。

## 七、接口契约（统一入口）

### 7.1 工具清单

| 工具 | 入参要点 | 说明 |
| --- | --- | --- |

| `slots.getSession` / `slots.closeSession` | `sessionId` | 会话查询 / 关闭 |
| `slots.simulate` | `gameId, spins, bet?, lines?, seed?` | RTP 自检 |
| `slots.validateConfigs` | `gameId?` | 契约校验 |
| `slots.reloadConfigs` | — | 热重载 |
| `slots.registerGame` | `config` | 运行时注入 CONFIG |
| `slots.history` | `gameId?, limit≤200` | 最近旋转记录（外部存储优先，失败回退内存） |
| `slots.leaderboard` | `gameId?, limit≤100` | 单次旋转最高倍率排行榜 |
| `store.health` | — | 外部存储驱动、延迟、降级与丢弃计数（含 R2 归档） |
| `store.archive` | — | 立即归档缓冲中的旋转流水到 R2 |
| `store.snapshot` | `name?` | 备份当前全部机台 CONFIG 快照（调参回滚点） |
| `blender.health` / `blender.renderSpin` | — / `gameId,grid` | 桥接状态 / 3D 演出 |
| `system.health` / `system.metrics` | — / `reset?` | 观测 |

### 7.2 `slots.spin` 返回要点

`roundId / gameId / phase / reelSet / bet / cost / grid[reel][row] / multiplier / lineWins[{line,symbol,count,positions,multiplier,pay}] /
scatterWins / bonusCells[{reel,row,value}] / wildMultipliers / expandedWilds / collect / triggered[] /
freeSpins / respins / nextPhase / totalWin / capped / balance / fairness{serverSeedHash,clientSeed,nonce}`

### 7.3 错误码

`-32700 ParseError`、`-32600 InvalidRequest`、`-32601 MethodNotFound`、`-32602 InvalidParams`、`-32603 InternalError`；
业务码：`-32001 GameNotFound`、`-32002 InvalidConfig`、`-32003 BetOutOfRange`、`-32004 SessionNotFound`、
`-32006 RateLimited`、`-32007 BudgetExceeded`、`-32010 UpstreamUnavailable`、`-32011 Timeout`。

## 九、验收标准（AC）

1. `npm run test` 全绿（当前 33/33）：引擎、判定、特性、校验、注册表、MCP 工具、熔断降级、存储降级、雪崩连锁、扩展符号、R2 签名与归档降级。
2. `npm run simulate`：8 台机台实测 RTP 均落在目标 ± tolerance（各跑 20 万轮）。
3. 新增一份 CONFIG 后，无需改动引擎与前端即可在大厅出现并可玩（hot reload 验证）。
4. `tools/call slots.spin` 对全部机台均返回合法盘面与结算。
5. 断掉 Blender 上游（或默认不配置）时，游戏流程完全正常，`blender.health` 返回 `degraded`。
6. 幂等键重复请求不重复扣款；超预算/超限流返回对应错误码。
7. 单份非法 CONFIG 只导致该机台下线，`/healthz` 中 `configFailures` 可见，其余机台可用。
8. 前端可完成：进机台 → 旋转 → 中奖演出 → 触发免费旋转/金币重旋 → 自动续转 → 返回大厅。

## 十、约束与风险

| 项 | 约束 / 风险 | 应对 |
| --- | --- | --- |
| 主题命名 | 不得使用真实商标/厂商名 | 采用通用主题命名（龙腾富贵 / 黄金法老 / 霓虹水果） |
| 资金合规 | 演示账本不可用于真金 | `WalletAdapter` 隔离，接入真实账务时替换实现 |
| RTP 偏差 | 抽样噪声（高波动机台尤甚） | ≥25 万轮自检；`tuning.payScale` 统一微调；CI 中加入区间断言 |
| 上游耦合 | Blender MCP 版本差异 | 桥接只依赖 `tools/call` 约定，失败即降级 |
| 内存会话 | 进程重启丢失 | TTL+LRU 控制规模；接口保持无状态可替换 |
| 前端无构建 | 依赖浏览器原生 ESM | 目标浏览器为现代内核；如需旧内核可后续加打包 |
| 引擎改动 | 可能破坏既有机台 | 基线机台 `classic-fruits` 作为回归基准纳入测试 |
| 外部存储故障 | DB/缓存不可用时拖垮旋转 | 存储门面自动降级内存：写入丢弃只记指标，读取回退快照，`store.health` 标记 `degraded` |
| 云端 DB 延迟 | 逐条写入放大往返耗时 | 旁路队列 + 批量事务落库 + 读前补写（实测 40 次旋转 RPC 共 264ms） |
| 多特性同轮命中 | 免费旋转与金币重旋状态互相覆盖 | 重旋进入 `pendingRespin` 排队，免费旋转结算后自动启动（有回归用例） |
| 雪崩倍率失控 | 连锁叠加导致 RTP 偏离与单轮爆表 | 段数上限 `maxSteps` + 阶梯末尾封顶 + 单轮封顶；`carryInFreeSpins` 默认关闭以控制免费旋转方差 |
| 对象存储不可达 | 归档链路拖慢或阻断旋转 | 独立旁路 + 4s 超时 + 失败即降级：仅丢弃并计数，主流程与数据库不受影响 |
| 出口网络策略 | 部分环境拦截 `*.r2.cloudflarestorage.com`（本机实测 TLS 握手失败） | 提供 `scripts/r2check.mjs` 自检；降级状态在 `store.health` 与前端标签可见，不影响交付验收 |
